Protocol

Nine fields, in order. Full rules in protocol.md.

1 Problem      which failure mode does this variant make less likely
2 Hypothesis   predicted behavior change, stated so it can be wrong
3 Baseline     current behavior, recorded before the change
4 Change       one variable only
5 Protocol     exact steps, runnable top to bottom
6 Observation  what was seen, raw — pasted, not paraphrased
7 Verdict      verified | not verified | uncertain | needs human judgment
8 Boundary     what the observation does not establish
9 Learning     what becomes easier to prevent: skill / test / rule / architecture

Rules

  • One variable per experiment. Two changes means two experiments.
  • Verdicts are never upgraded for convenience. uncertain is a real result.
  • Retired variants stay linked so results remain comparable over time.
  • A longer report is not a better experiment.
  • Codes are allocated when reserved, never reused, and never versioned with suffixes — history lives in git.

Addressing

Each experiment has one code and one directory, proto<N> → lab/proto<N>/. To direct work, name the code. improve proto1 means edit lab/proto1/ and its registry row — nothing else, because the other variants are the comparison baseline.
